# Bootstrap Gruntwork Pipelines — Azure + GitHub

This runbook installs [Gruntwork Pipelines](https://docs.gruntwork.io/2.0/docs/pipelines/concepts/overview)
(Terragrunt Scale) into a GitHub `infrastructure-live` repository and bootstraps it against one
**Azure** subscription. It handles both starting points:

- **A repository that is not yet set up for Terragrunt Scale.** The full repository layout is rendered
  into it — `root.hcl`, `.mise.toml`, `.gitignore`, `.gruntwork/`, the workflows, and the first
  subscription's bootstrap stack.
- **A repository that already has a `root.hcl`.** Only the new subscription's directory and bootstrap
  stack are added; your existing configuration is left alone.

Which one applies is detected from the repository itself after it is cloned — you do not choose.

It then provisions the Entra ID (Azure AD) trust that lets your GitHub Actions workflows authenticate
to Azure with no long-lived secrets: an application and service principal for `terragrunt plan`, one
for `terragrunt apply`, federated identity credentials binding each to your repository's OIDC tokens,
and the Blob Storage resources that hold OpenTofu state.

<Admonition
  type="warning"
  title="This provisions real cloud resources"
  description="The bootstrap step creates Entra ID applications, service principals, custom roles, role assignments, and a Storage Account for state in the Azure subscription you authenticate to. You need Owner (Azure RBAC) plus Application Administrator (Entra ID directory role) on that subscription. Run this only against a subscription you own and intend to manage with Pipelines."
/>

<Admonition
  type="warning"
  title="Prerequisite: the repository must already exist"
  description="This runbook does not create the repository. Create it on GitHub first — typically named `infrastructure-live` — and **tick 'Add a README file'** so it starts with a commit on its default branch. An existing Terragrunt Scale repository works too; you select either in the clone step below."
/>

<Admonition
  type="note"
  title="Prerequisite: configure SCM access for Pipelines"
  description="Gruntwork Pipelines needs access to your repository to fetch your IaC code, reusable CI/CD code, and the Pipelines binary itself. Before you begin, set this up via the [Gruntwork.io GitHub App](https://docs.gruntwork.io/2.0/docs/pipelines/installation/viagithubapp) (recommended) or [machine users](https://docs.gruntwork.io/2.0/docs/pipelines/installation/viamachineusers). This is separate from the GitHub sign-in this runbook uses to clone the repo and open the pull request."
/>

## 6. Configure the bootstrap

Fill in the values that cannot be derived automatically.

<Inputs id="config" title="Bootstrap settings">
```yaml
variables:
  - name: SubscriptionName
    type: string
    description: A short name for this Azure subscription (e.g. "dev", "prod"). Becomes the top-level directory and the Pipelines environment name.
    validations:
      - required
    x-section: Subscription

  - name: AzureLocation
    type: string
    description: The Azure region for the state-backend resources (e.g. eastus, westeurope). Use `az account list-locations -o table` to list options.
    default: eastus
    validations:
      - required
    x-section: Subscription

  - name: StateResourceGroupName
    type: string
    description: Name of the Azure Resource Group that will hold the OpenTofu state Storage Account.
    validations:
      - required
    x-section: State

  - name: StateStorageAccountName
    type: string
    description: Name of the Azure Storage Account for OpenTofu state. Must be globally unique, 3-24 characters, lowercase letters and numbers only.
    validations:
      - required
    x-section: State

  - name: StateStorageContainerName
    type: string
    description: Name of the Blob container inside the Storage Account that holds state files.
    default: tfstate
    validations:
      - required
    x-section: State

  - name: OIDCResourcePrefix
    type: string
    description: Prefix for the OIDC Entra ID resources. Creates <prefix>-plan and <prefix>-apply applications.
    default: pipelines
    validations:
      - required
    x-section: OIDC

  - name: IncludeDriftDetection
    type: bool
    description: Whether to generate the scheduled drift-detection workflow (.github/workflows/pipelines-drift-detection.yml).
    default: true
    x-section: Workflow

  - name: Issuer
    type: string
    description: Optional override for the OIDC issuer URL. Leave as "default" to use GitHub's default (https://token.actions.githubusercontent.com).
    default: "default"
    validations:
      - required
    x-section: OIDC

  - name: OverwriteWorkflows
    type: bool
    description: When false (default), the CI workflow files are written only if they don't already exist, so bootstrapping an additional account into a repo that already has Pipelines won't overwrite (or revert customizations to) its workflows. Set true to force-refresh them.
    default: false
    x-section: Advanced

  - name: TerragruntScaleCatalogRef
    type: string
    description: 'Pin a specific Terragrunt Scale catalog ref (e.g. v1.13.1), or leave it as \"latest\" to use the newest release, resolved automatically before the generate step.'
    default: \"latest\"
    validations:
      - required
    x-section: Advanced

  - name: IaCTool
    type: enum
    description: 'The IaC binary Pipelines instructs Terragrunt to use. Gruntwork recommends OpenTofu; choose terraform only if your organisation requires it. A repository that already declares a tool keeps it — this choice applies to new configuration only.'
    options:
      - opentofu
      - terraform
    default: opentofu
    validations:
      - required
    x-section: Advanced

  - name: TerraformVersion
    type: string
    description: Terraform version to pin, used only when IaCTool is "terraform" and the repository has no mise config yet.
    default: "1.15.9"
    x-section: Advanced

  - name: TerragruntVersion
    type: string
    description: Terragrunt version to pin in the repository's .mise.toml. Optional — leave as the default unless you need a specific version.
    default: "1.0.0"
    x-section: Advanced

  - name: OpenTofuVersion
    type: string
    description: OpenTofu version to pin in the repository's .mise.toml. Optional.
    default: "1.11.5"
    x-section: Advanced
```
</Inputs>

**You're done.** The setup pull request was committed with `[skip ci]`, so opening it does **not** kick off a Pipelines run — you applied this bootstrap locally on purpose, so Pipelines never runs against half-configured infrastructure. Once you **merge** it to `{{ .inputs.DeployBranch }}`, Gruntwork Pipelines is activated: from then on it runs `plan` on pull requests and `apply` on merges to `{{ .inputs.DeployBranch }}` for changes under `{{ .inputs.SubscriptionName }}/`. To add another subscription later, re-run
this runbook and choose a new `SubscriptionName`.
