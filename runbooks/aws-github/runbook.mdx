# Bootstrap Gruntwork Pipelines — AWS + GitHub

This runbook installs [Gruntwork Pipelines](https://docs.gruntwork.io/2.0/docs/pipelines/concepts/overview)
(Terragrunt Scale) into a GitHub `infrastructure-live` repository and bootstraps it against one **AWS**
account. It handles both starting points:

- **A repository that is not yet set up for Terragrunt Scale.** The full repository layout is rendered
  into it — the root `root.hcl`, `.mise.toml`, `.gitignore`, `.gruntwork/`, the `.github/workflows`
  Pipelines workflows, and the first account's bootstrap stack.
- **A repository that already has a `root.hcl`.** Only the new account's directory and bootstrap stack
  are added; your existing configuration is left alone.

Which one applies is detected from the repository itself after it is cloned — you do not choose.

It then provisions, for that account, the OIDC trust that lets your GitHub Actions workflows authenticate
to AWS with no long-lived credentials:

- an IAM OpenID Connect provider for GitHub Actions,
- an IAM role for `terragrunt plan` (read-only, used on pull requests), and
- an IAM role for `terragrunt apply` (used on merges to your deploy branch).

Wherever a value can be discovered automatically, this runbook does it for you — your AWS account ID and
partition come from your authenticated identity, and the numeric GitHub org/repo IDs (used for GitHub's
immutable OIDC subject claims) come from the clone step. You only fill in what genuinely cannot be
derived.

## 6. Configure the bootstrap

Fill in the values that cannot be derived automatically. Everything else is supplied for you from the
steps above.

<Inputs id="config" title="Bootstrap settings">
```yaml
variables:
  - name: AccountName
    type: string
    description: A short name for this AWS account (e.g. "dev", "prod"). Becomes the top-level directory and the Pipelines environment name.
    validations:
      - required
    x-section: Account

  - name: AWSRegion
    type: string
    description: The AWS region used for provider configuration and API calls when managing global resources.
    default: us-east-1
    validations:
      - required
    x-section: Account

  - name: StateBucketName
    type: string
    description: Name of the S3 bucket for OpenTofu state. Must be globally unique and obey S3 naming rules.
    validations:
      - required
    x-section: State

  - name: OIDCResourcePrefix
    type: string
    description: Prefix for the OIDC IAM resources. Creates <prefix>-plan and <prefix>-apply roles.
    default: pipelines
    validations:
      - required
    x-section: OIDC

  - name: IncludeDriftDetection
    type: bool
    description: Whether to generate the scheduled drift-detection workflow (.github/workflows/pipelines-drift-detection.yml).
    default: true
    x-section: Workflow

  - name: OverwriteWorkflows
    type: bool
    description: When false (default), the CI workflow files are written only if they don't already exist, so bootstrapping an additional account into a repo that already has Pipelines won't overwrite (or revert customizations to) its workflows. Set true to force-refresh them.
    default: false
    x-section: Advanced

  - name: TerragruntScaleCatalogRef
    type: string
    description: 'Pin a specific Terragrunt Scale catalog ref (e.g. v1.13.1), or leave it as \"latest\" to use the newest release, resolved automatically before the generate step.'
    default: \"latest\"
    validations:
      - required
    x-section: Advanced

  - name: IaCTool
    type: enum
    description: 'The IaC binary Pipelines instructs Terragrunt to use. Gruntwork recommends OpenTofu; choose terraform only if your organisation requires it. A repository that already declares a tool keeps it — this choice applies to new configuration only.'
    options:
      - opentofu
      - terraform
    default: opentofu
    validations:
      - required
    x-section: Advanced

  - name: TerraformVersion
    type: string
    description: Terraform version to pin, used only when IaCTool is "terraform" and the repository has no mise config yet.
    default: "1.15.9"
    x-section: Advanced

  - name: TerragruntVersion
    type: string
    description: Terragrunt version to pin. Used only when the repository has no mise config yet — an existing .mise.toml is never modified.
    default: "1.0.0"
    x-section: Advanced

  - name: OpenTofuVersion
    type: string
    description: OpenTofu version to pin. Used only when the repository has no mise config yet — an existing .mise.toml is never modified.
    default: "1.11.5"
    x-section: Advanced
```
</Inputs>

## 9. Open a pull request

Commit the generated configuration and open a pull request against your repository. The commit is tagged
`[skip ci]`, so opening it does not start a Pipelines run — you have already applied the bootstrap
locally. After it merges to your deploy branch, Pipelines takes over.

**You're done.** The setup pull request was committed with `[skip ci]`, so opening it does **not** kick off a Pipelines run — you applied this bootstrap locally on purpose, so Pipelines never runs against half-configured infrastructure. Once you **merge** it to `{{ .inputs.DeployBranch }}`, Gruntwork Pipelines is activated: from then on it runs `plan` on pull requests and `apply` on merges to `{{ .inputs.DeployBranch }}` for changes under `{{ .inputs.AccountName }}/`. To add another account later, re-run this runbook against the same repository and choose a new `AccountName`.
