# Bootstrap Gruntwork Pipelines — AWS + GitHub (existing repository)

This runbook installs [Gruntwork Pipelines](https://docs.gruntwork.io/2.0/docs/pipelines/concepts/overview)
(Terragrunt Scale) into an **existing** `infrastructure-live` repository hosted on **GitHub**, targeting
one **AWS** account.

It provisions, per account, the OIDC trust that lets your GitHub Actions workflows authenticate to AWS
with no long-lived credentials:

- an IAM OpenID Connect provider for GitHub Actions,
- an IAM role for `terragrunt plan` (read-only, used on pull requests), and
- an IAM role for `terragrunt apply` (used on merges to your deploy branch).

Wherever a value can be discovered automatically, this runbook does it for you — your AWS account ID and
partition come from your authenticated identity, and the numeric GitHub org/repo IDs (used for GitHub's
immutable OIDC subject claims) are fetched with the `gh` CLI. You only fill in what genuinely cannot be
derived.

<Admonition
  type="warning"
  title="This provisions real cloud resources"
  description="The bootstrap step creates IAM roles, an OIDC provider, and an S3 state bucket in the AWS account you authenticate to. Run this only against an account you own and intend to manage with Pipelines."
/>

<Admonition

## 6. Configure the bootstrap

Fill in the values that cannot be derived automatically. Everything else is supplied for you from the
steps above.

<Inputs id="config" title="Bootstrap settings">
```yaml
variables:
  - name: AccountName
    type: string
    description: A short name for this AWS account (e.g. "dev", "prod"). Becomes the top-level directory and the Pipelines environment name.
    validations:
      - required
    x-section: Account

  - name: AWSRegion
    type: string
    description: The AWS region used for provider configuration and API calls when managing global resources.
    default: us-east-1
    validations:
      - required
    x-section: Account

  - name: StateBucketName
    type: string
    description: Name of the S3 bucket for OpenTofu state. Must be globally unique and obey S3 naming rules.
    validations:
      - required
    x-section: State

  - name: OIDCResourcePrefix
    type: string
    description: Prefix for the OIDC IAM resources. Creates <prefix>-plan and <prefix>-apply roles.
    default: pipelines
    validations:
      - required
    x-section: OIDC

  - name: DeployBranch
    type: string
    description: The branch Pipelines deploys from. Merges here trigger apply; this branch is granted the apply role.
    default: main
    validations:
      - required
    x-section: OIDC

  - name: OverwriteWorkflows
    type: bool
    description: When false (default), the CI workflow files are written only if they don't already exist, so bootstrapping an additional account into a repo that already has Pipelines won't overwrite (or revert customizations to) its workflows. Set true to force-refresh them.
    default: false
    x-section: Advanced

  - name: TerragruntScaleCatalogRef
    type: string
    description: 'Optional: pin a specific Terragrunt Scale catalog ref (e.g. v1.13.1). Leave blank to use the latest release, resolved automatically before the generate step.'
    default: ""
    x-section: Advanced

  - name: TerragruntVersion
    type: string
    description: Terragrunt version to pin in the repository's .mise.toml. Optional — leave as the default unless you need a specific version.
    default: "1.0.0"
    x-section: Advanced

  - name: OpenTofuVersion
    type: string
    description: OpenTofu version to pin in the repository's .mise.toml. Optional.
    default: "1.11.5"
    x-section: Advanced
```
</Inputs>

## 7. Generate the bootstrap configuration

Render the `aws/github/account` template into your repository. This writes
`<AccountName>/_global/bootstrap/terragrunt.stack.hcl`, `<AccountName>/account.hcl`,
`<AccountName>/_global/region.hcl`, and `.gruntwork/environment-<AccountName>.hcl`.

Before generating, resolve the latest catalog release so the bootstrap pins the newest version
automatically (unless you pinned a specific `TerragruntScaleCatalogRef` above).

## 8. Add the GitHub Actions workflow

Add the Pipelines GitHub Actions workflows — the plan/apply workflow plus the unlock and
drift-detection workflows. Each file is written only if it is missing, so re-running this against a
repo that already has Pipelines (for example when adding another account) won't clobber your
workflows; set `OverwriteWorkflows` in the form above to force-refresh them.

<Command
  id="add-ci-workflows"

Commit the generated configuration and open a PR against your repository. Opening the PR does not start a Pipelines run — the commit is tagged `[skip ci]`, and you have already applied the bootstrap locally. After it merges to your deploy branch, Pipelines takes over.

**You're done.** The setup pull request was committed with `[skip ci]`, so opening it does **not** kick off a Pipelines run — you applied this bootstrap locally on purpose, so Pipelines never runs against half-configured infrastructure. Once you **merge** it to `{{ .inputs.DeployBranch }}`, Gruntwork Pipelines is activated: from then on it runs `plan` on pull requests and `apply` on merges to `{{ .inputs.DeployBranch }}` for changes under `{{ .inputs.AccountName }}/`. To add another account later, re-run this runbook
and choose a new `AccountName`.
